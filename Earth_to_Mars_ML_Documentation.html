01 / Concept

What the project does

Exploring departure dates and transfer durations with a numerical three-body-plus-Sun spacecraft model is expensive because each candidate needs repeated numerical integration and shooting correction. This project trains a surrogate to predict the two impulsive delta-v magnitudes (Earth departure and Mars capture) so thousands of options can be screened before physical verification.

Departure date + TOF
→
Ephemerides + Lambert guess
→
N-body shooting labels
→
13-feature MLP
→
Screen → verify → refine

Key distinction: The MLP predicts delta-v magnitudes, not the full three-dimensional trajectory or initial velocity direction. Only the physical shooting correction is intended to target the specified Mars SOI point.

02 / Install

Project files and dependencies

Use Python 3.10 or newer. Place the two supplied scripts together in one working directory. Training produces the model bundle used by testing.

project/
  mars_nbody_mlv2.py            # Physical solver, data generation, MLP training
  testmodelTOFml_cleaned.py    # Interactive tests, TOF searches, optimum window
  mars_nbody_surrogate.joblib  # Generated by training
python -m pip install numpy scipy pandas scikit-learn matplotlib joblib

Quick start:

python mars_nbody_mlv2.py --samples 500
python testmodelTOFml_cleaned.py

Commands should be run from the project directory. The testing script imports mars_nbody_mlv2 and by default loads mars_nbody_surrogate.joblib.

03 / Learn

Generate the dataset and train the MLP

# Small smoke test (at least 20 accepted samples required)
python mars_nbody_mlv2.py --samples 30 --skip-plots

# Larger initial training experiment
python mars_nbody_mlv2.py --samples 500

Training draws departure dates from 2026-01-01 to before 2040-01-01 and transfer durations from 120 to 350 days by default. The physical solver uses approximate Keplerian planetary states, a Lambert-informed initial guess, DOP853 numerical integration and a least-squares shooting correction; unsuccessful physically checked candidates are discarded. A standard-scaled MLP uses 13 planetary state/TOF inputs, hidden layers (128, 64) and two outputs.

FlagBehavior
--samples NAccepted transfer examples; default 1000.
--seed NDataset sampling and train/test split seed; default 42.
--start-date / --end-dateTraining departure-date limits (end excluded).
--tof-min / --tof-maxTraining transfer-duration limits.
--skip-plotsSkip validation and porkchop plotting.
--no-save-csvSkip saving the training dataset.

The held-out metrics are printed by the training script: MAE for departure/arrival and total delta-v, total RMSE, and total R². The porkchop map is ML-predicted transfer cost, not a map of physically verified arrivals.

04 / Test

Four interactive search modes

python testmodelTOFml_cleaned.py

Without a mode flag or a fixed --tof-days, the test script asks you to choose a search mode. Press Enter for Option 1. Modes 1–3 prompt for departure date/TOF range; Option 4 requests a launch window.

1

Physics-only

Coarse and fine fixed-date TOF search using direct N-body solves. Slowest baseline.

2

ML-guided

ML ranks TOFs at one departure date; several shortlisted cases are physically verified and refined.

3

ML-only choice

Selects the lowest ML-predicted TOF; one N-body solve checks it against physics.

4

Optimum launch window

Searches departure date and TOF. N-body verifies shortlisted pairs and refines the best.

Noninteractive commands

python testmodelTOFml_cleaned.py --physics-tof-search --no-show
python testmodelTOFml_cleaned.py --ml-tof-search --no-show
python testmodelTOFml_cleaned.py --ml-only-tof --no-show
python testmodelTOFml_cleaned.py --optimum-window --no-show

# Fixed departure and fixed TOF (no search)
python testmodelTOFml_cleaned.py --departure-date 2031-09-01 --tof-days 240 --no-show

The default fixed departure is 2030-09-01, and its requested TOF range is 150–400 days. ML-driven fixed-date scanning is restricted to the surrogate training TOF interval (default 120–350 days), so the effective default ML range is 150–350 days.

05 / Optimize

Option 4: optimized launch-window search

Option 4 forms an equally spaced departure-date × TOF grid, computes batched ML delta-v predictions, ranks the lowest values, and selects up to the requested number of separated candidates for physical N-body shooting verification. The selected verified candidate is improved using a 3 × 3 local physical refinement grid.

Prompt / flagDefaultMeaning
Window start / end2026-01-01 / 2026-12-31Dates considered in the grid
Minimum / maximum TOF120 / 350 daysClipped to training TOF range
Departure samples90Number of departure grid coordinates
TOF samples55Number of TOF grid coordinates
Physical candidates8Number of ML-ranked candidates to check physically

Example: search across 2026–2030

python testmodelTOFml_cleaned.py --optimum-window --window-start 2026-01-01 --window-end 2030-12-31 --window-tof-min 120 --window-tof-max 350 --window-departure-samples 100 --window-tof-samples 100 --window-candidates 10 --no-show

The same parameters can be entered interactively after selecting Option 4. The 100 × 100 grid performs 10,000 ML predictions, not 10,000 N-body integrations. Shortlist candidates are separated using departure-time/TOF distance constraints to avoid evaluating nearly identical grid points.

Optimum means best found, not certified global optimum. A finite coarse grid, ML ranking errors, solver acceptance, shortlist size, and local refinement all affect the solution discovered.

06 / Interpret

Corrected vs uncorrected trajectory and log–log distance

The latest Option 4 code uses the same two-panel comparison format as Options 1–3:

Left • Heliocentric orbit (AU)

Earth/Mars orbital reference curves, the Sun, planetary departure/arrival markers, and both corrected N-body and uncorrected ML paths, including closest approaches.

Right • Mars distance (log–log)

Spacecraft-to-Mars separation versus days after departure for both paths. The horizontal standard Mars sphere-of-influence (SOI) reference helps assess encounter.

  • Corrected: the N-body shooting solver adjusts the departure velocity to reach its Mars SOI target.
  • Uncorrected ML: predicted departure delta-v magnitude plus Lambert/boundary-derived direction, propagated with Sun, Earth and Mars gravity, with no shooting correction.
  • Scale: distance for the ML comparison is shown in thousands of kilometres; log–log display excludes time zero.
  • SOI conventions: the physical solver targets approximately 0.7 × the standard Mars SOI radius; the test comparison plots the standard radius. Zero miss printed to 0.000 km is rounded.

Do not equate a low delta-v prediction with a successful intercept. SOI entry itself also does not imply surface landing or successful capture.

The ML minimum was not the lowest-cost physically verified solution. That gap is why the algorithm validates a shortlist and refines locally. The final transfer is the best verified solution found by this search configuration, not proof of a global minimum.

09 / Research rigor

Validation, limitations and next experiments

What is included in the physical baseline

  • Approximate Earth/Mars Keplerian ephemerides and a heliocentric frame.
  • Solar, terrestrial and Martian gravity, with indirect terms in the non-inertial heliocentric formulation.
  • Lambert-derived initial guess; DOP853 integration and least-squares shooting.
  • Hyperbolic excess estimates and impulsive burns from assumed parking orbits (Earth 200 km, Mars 250 km).

What is outside scope

High-precision planetary ephemerides, separate lunar gravity, other planets, solar radiation pressure, finite-burn propulsion, detailed launch/capture geometry, landing dynamics, and proof of global optimality. The model is educational and exploratory, not flight-quality.

Strong next comparisons

  1. Compare physics-only and ML-guided searches on the same departure-date and TOF grid; report wall time, number of N-body solves, and best verified total delta-v.
  2. Report held-out MAE/RMSE/R² from the actual training run, and test an unseen block of departure dates instead of relying only on a random split.
  3. Evaluate how accurately the MLP ranks low-delta-v candidates, not only its pointwise prediction error.
  4. Repeat benchmark runs and report variability before claiming a robust speed-up.

Research question: Can a surrogate sharply reduce Earth-to-Mars launch-window screening cost while preserving the quality of physically verified transfer solutions?

10 / Troubleshoot

Common issues

SymptomAction
Missing model bundleTrain first or provide the path using --model-file.
Physical module import failsEnsure mars_nbody_mlv2.py is alongside the test script and has not been renamed.
Plot window never opensUse --no-show and open the saved PNG directly.
TOF values are clippedML scanning uses the training TOF bounds by design (default 120–350 days).
Shortlisted transfer failsPhysical verification may reject low predicted delta-v; try additional candidates or a different search range.
Want a fixed caseUse --departure-date YYYY-MM-DD --tof-days N.
Want a repeatable batch runSupply explicit flags rather than relying on the interactive prompts.
